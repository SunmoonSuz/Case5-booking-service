## Слайд 2. Заказчик, контекст и проблема бизнеса
- **Целевой заказчик:** Предприятия сферы услуг (барбершопы, салоны красоты, сервисные центры, медицинские кабинеты) со штатом 3–25 специалистов.
- **Ключевые боли при ручной записи (телефон / мессенджеры):**
  1. **Двойное бронирование (овербукинг):** два клиента записываются на одно время к одному мастеру при параллельной обработке заявок.
  2. **Потеря до 22% клиентов** в нерабочие часы (вечер/ночь), когда администратор не отвечает.
  3. **До 60% времени администратора** уходит на переписку по выбору свободных окон и переносам визитов.
  4. **Рассинхронизация цен и графиков:** изменение расписания или прайса ломает историю текущих записей.

## Слайд 3. Исходные материалы и оговорка об учебных данных
- **Демонстрационный набор данных (`DemoDataBootstrapRunner`):**

  - 3 специалиста с матрицей компетенций `M:N` и 7-дневным графиком смен (`10:00–14:00`, перерыв `14:00–15:00`, `15:00–20:00`).
  - Готовые тестовые аккаунты: Клиент (`client@booking.local`) и Администратор (`admin@booking.local`).
- **⚠️ Важное предупреждение (согласно Положению о Форуме):**
  - **Источник и метод:** данные сгенерированы программным сидером по синтетическому шаблону предприятия сферы услуг.
  - **Обоснование:** структура отражает реальные сменные графики, обеденные перерывы и пересечение длительностей 30/60 минут.
  - **Этическая и юридическая оговорка:** персональные данные реальных граждан не используются (152-ФЗ). Домен `@booking.local` и номера `+7900000000X` являются фиктивными учебными идентификаторами.

## Слайд 4. Архитектура решения и стек технологий
- **Backend (Модульный монолит на Kotlin 2.0 / Java 21 LTS):**
  - `Spring Boot 3.3.5`, `Spring Security` (HttpOnly Cookie `JSESSIONID`, `BCrypt cost 12`), `Spring Data JPA` + `Flyway`.
  - Включены виртуальные потоки **Java 21 Virtual Threads** для масштабируемой обработки конкурентных запросов.
- **База данных (PostgreSQL 16):**
  - Реляционная схема из 6 таблиц с расширением `btree_gist` и хранением времени в `UTC` (`TIMESTAMPTZ`).
- **Frontend (React 18 + TypeScript 5.6 + Vite 6):**
  - `TanStack Query v5` для реактивной синхронизации слотов, `Tailwind CSS` для мобильной адаптивности (`>= 360px`).

## Слайд 5. Гарантия отсутствия двойного бронирования (Критерий приёмки №1)
- **Проблема обычных решений:** проверка `if (isSlotFree)` в коде приложения уязвима к гонке потоков (`Race Condition / TOCTOU`).
- **Наше инженерное решение (Уровень ядра СУБД):**
  ```sql
  ALTER TABLE bookings ADD CONSTRAINT no_overlapping_active_bookings
  EXCLUDE USING gist (
      master_id WITH =,
      (tstzrange(start_time, end_time, '[)')) WITH &&
  ) WHERE (status IN ('PENDING', 'CONFIRMED'));
  ```
- **Доказательство надёжности:**
  - Интеграционный стресс-тест `OverbookingConcurrencyIntegrationTest` запускает **20 параллельных потоков одновременно** (через `CyclicBarrier`) на один слот.
  - **Результат:** ровно **1 запись** получает `201 Created`, остальные **19 потоков** получают `409 Conflict (SLOT_ALREADY_BOOKED)`, а UI мгновенно обновляет сетку слотов.

## Слайд 6. Клиентский путь и Личный кабинет (Критерий приёмки №2)
- **4-шаговый мастер записи (`BookingFlow`):**
  1. Выбор услуги (`30` или `60` мин) -> 2. Выбор мастера -> 3. Выбор даты (горизонт 30 дней) -> 4. Выбор свободного слота (`Europe/Moscow`).
- **Безопасность и защита персональных данных:**
  - Публичное API `/api/v1/availability` отдаёт только свободные интервалы без раскрытия чужих записей.
  - Личный кабинет (`/api/v1/bookings/my`) доступен строго авторизованному владельцу (`ROLE_CLIENT`), защищён от `IDOR`-атак (`403 ACCESS_DENIED` при попытке обращения к чужому `UUID`).
- **Управление визитами:** разделение на «Активные» и «Историю», отмена будущей записи в 1 клик с мгновенным возвратом слота в пул доступных.

## Слайд 7. Административная панель и синхронизация расписания (Критерий приёмки №3)
- **4 функциональных модуля администратора (`ROLE_ADMIN`):**
  1. **Модерация записей:** фильтрация по дате/мастеру/статусу, переходы `PENDING -> CONFIRMED / REJECTED`, `CONFIRMED -> COMPLETED / CANCELLED`.
  2. **Управление расписанием (`ScheduleTab`):** настройка рабочих интервалов и перерывов по дням недели (`Пн–Вс`) с валидацией пересечений.
  3. **Управление каталогом услуг:** создание/редактирование услуг, паттерн `Price Snapshot` (сохранение исторической цены в созданных бронях).
  4. **Управление мастерами:** привязка услуг и защита от деактивации ресурса при наличии активных будущих записей (`409 ACTIVE_BOOKINGS_EXIST`).
- **Мгновенное отражение на клиенте:** любое изменение графика мастера сразу пересчитывает доступные слоты в клиентском интерфейсе.
