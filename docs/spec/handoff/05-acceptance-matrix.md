В БД создаётся запись бронирования со статусом `PENDING`. На экране отображается номер заявки и статус «Ожидает подтверждения». Слот блокируется в расписании. | E2E / Integration |

В клиентском каталоге немедленно появляются добавленная услуга, мастер и доступные слоты по заданному графику. | E2E / Integration |

## 2. Негативные и граничные проверки

| AC ID | Сценарий | Некорректные / граничные данные | Ожидаемое поведение |
|---|---|---|---|
| `AC-EDGE-001` | `SCN-002`, `BR-001` | Запись на смежные интервалы: Запись 1 на $[10:00, 11:00)$, Запись 2 на $[11:00, 12:00)$ к одному мастеру. | Обе записи успешно создаются. Момент $11:00$ является границей полуинтервалов $[10:00, 11:00)$ и $[11:00, 12:00)$, коллизии нет. |
| `AC-EDGE-002` | `SCN-002`, `BR-001` | Частично перекрывающиеся интервалы: мастер занят на $[10:00, 11:00)$, клиент пытается записаться на $[10:30, 11:30)$. | Сервер отклоняет запрос с ошибкой `409 Conflict`, так как интервалы пересекаются на $[10:30, 11:00)$. |
| `AC-EDGE-003` | `SCN-001`, `BR-005` | Регистрация с уже существующим email (без учета регистра букв: `Test@example.com` и `test@example.com`). | Сервер возвращает ошибку `400 Bad Request` / `409 Conflict` («Email уже используется»), дублирование учетных записей исключено. |
| `AC-EDGE-004` | `SCN-001`, `BR-005` | Ввод пароля длиной 7 символов (менее допустимого минимума 8). | Валидация на клиенте и бэкенде отклоняет регистрацию с сообщением «Пароль должен содержать не менее 8 символов». |
| `AC-EDGE-005` | `SCN-004`, `BR-004` | Попытка отмены бронирования, время начала которого уже наступило ($T_{start} \le T_{now}$). | Бэкенд возвращает `400 Bad Request` («Нельзя отменить услугу, время которой уже наступило»). Статус записи не меняется. |
| `AC-EDGE-006` | `SCN-002` | Попытка бронирования слота за пределами рабочих часов мастера (например, мастер работает до 18:00, запрос на слот $[18:00, 19:00)$). | Бэкенд отклоняет запрос с `400 Bad Request` («Выбранное время выходит за рамки графика работы специалиста»). |
| `AC-EDGE-007` | `SCN-005` | Повторное подтверждение или отклонение уже обработанной заявки (`CONFIRMED` $\to$ `REJECTED` без отмены). | Запрет недопустимых переходов состояний. Бэкенд возвращает `400 Bad Request` («Недопустимый переход статуса»). |
| `AC-EDGE-008` | `SCN-002`, `BR-006` | Попытка отправки клиентом заявки на бронирование прошедшего временного слота ($T_{start} \le T_{now}$). | Бэкенд отклоняет запрос с кодом `400 Bad Request` («Нельзя забронировать время в прошлом»). Заявка не создается. |
| `AC-EDGE-009` | `SCN-005` | Указание некорректного интервала рабочих часов мастера (время окончания смены меньше или равно времени начала). | Валидация панели администратора и бэкенда отклоняет сохранение расписания с ошибкой `400 Bad Request`. |
