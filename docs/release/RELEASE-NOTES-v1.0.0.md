## 1. Included Capabilities (Реализованный функционал)

### 1.1. Клиентский пользовательский опыт (Web UI & Client Flow)
- **Каталог услуг и мастеров (REQ-003, REQ-010, REQ-011):**
  - Просмотр каталога с ценами (в RUB), фиксированной длительностью (30 или 60 мин) и описанием.
  - Фильтрация мастеров, привязанных к выбранной услуге.
- **Интерактивный выбор даты и времени (REQ-004, REQ-005, AC-002):**
  - Горизонт планирования на 30 календарных дней вперед.
  - Динамический расчёт свободных интервалов: отсечение прошедших слотов, исключение обеденных перерывов мастеров и пересечений с существующими активными бронированиями (`PENDING`, `CONFIRMED`).
  - Принудительное отображение в таймзоне салона `Europe/Moscow` независимо от часового пояса клиента (`AC-010`, `ADR-007`).
- **Бронирование слота и гарантия от овербукинга (REQ-006, REQ-007, AC-003, AC-004, NFR-001):**
  - Оформление брони со статусом `PENDING` (удержание слота на модерацию администратора).
  - Снапшот цен и названий услуг на момент записи (`ADR-011`).
  - **Критичный сценарий AC-004:** При попытке одновременного бронирования одного слота двумя клиентами второй получает HTTP 409 `SLOT_ALREADY_BOOKED`. Фронтенд перехватывает ошибку, отображает Toast-уведомление и мгновенно инвалидирует кэш TanStack Query, обновляя сетку слотов **без перезагрузки всей страницы**.
- **Личный кабинет клиента (REQ-008, REQ-009, AC-005):**
  - Разделение записей на вкладки «Активные» (сортировка по возрастанию даты) и «История» (по убыванию).
  - Возможность самостоятельной отмены записи клиентом строго до наступления времени начала визита ($T_{start} > now$).

### 1.2. Административная панель (Admin Moderation & Management)
- **Модерация заявок (REQ-013, REQ-014, AC-006, AC-007, AC-009):**
  - Единая таблица заявок с фильтрами по статусу (`ALL`, `PENDING`, `CONFIRMED`, `CANCELLED`, `REJECTED`, `COMPLETED`), мастеру и дате.
  - Подтверждение заявки (`PENDING` $\to$ `CONFIRMED`).
  - Отклонение с обязательным указанием причины (`PENDING` $\to$ `REJECTED`).
  - Отмена визита администратором (`CONFIRMED` $\to$ `CANCELLED`).
  - Успешное завершение визита (`CONFIRMED` $\to$ `COMPLETED`).
- **Управление каталогом услуг (REQ-010):**
  - Добавление, редактирование названия/описания/цены, деактивация услуг.
  - Запрет изменения длительности услуги при наличии активных будущих записей (`ADR-012`).
- **Управление мастерами (REQ-011):**
  - Добавление, редактирование, деактивация мастеров.
  - Матрица привязки услуг к мастеру.
  - Запрет деактивации мастера при наличии будущих активных записей (`ADR-012`).
- **Управление расписанием и сменами (REQ-012, AC-009):**
  - Настройка рабочих интервалов по дням недели.
  - Поддержка обеденных перерывов мастера.
  - Клиентская и серверная валидация корректности интервалов ($Start < End$, отсутствие наложений).

### 1.3. Безопасность и архитектурные инварианты
- **Защита от овербукинга на уровне СУБД (ADR-004, NFR-001):**
  - PostgreSQL 16 с расширением `btree_gist` и частичным GiST exclusion constraint:
    `EXCLUDE USING gist (master_id WITH =, (tstzrange(start_time, end_time, '[)')) WITH &&) WHERE (status IN ('PENDING', 'CONFIRMED'))`.
  - Математическая гарантия невозможности двойной записи даже при миллисекундных параллельных гонках.
- **Аутентификация и сессии (REQ-001, REQ-002, AC-001, AC-008, ADR-005):**
  - Хэширование паролей алгоритмом `BCryptPasswordEncoder(12)`.
  - Cookie-сессии `JSESSIONID` с флагами `HttpOnly`, `SameSite=Lax`.
  - Response interceptor Axios для автоматического сброса авторизации при HTTP 401.
  - Идемпотентная инициализация администратора по умолчанию через `AdminBootstrapRunner`.
- **Единый часовой пояс (ADR-007, ASM-006, AC-010):**
  - Серверное хранилище и REST API работают строго в UTC (`Instant`, `TIMESTAMPTZ`).
  - Интерфейс фронтенда принудительно форматирует время по `Europe/Moscow`.
- **Адаптивность и доступность (NFR-003):**
  - Вёрстка адаптирована под экраны от 360px.
  - Все тач-таргеты интерактивных элементов имеют размер $\ge 44 \times 44$px.
  - Реализован Focus Trap в модальных окнах (`Modal.tsx`).

## 5. How to Run / Demo (Инструкция по запуску)

### Шаг 1: Запуск базы данных PostgreSQL
```bash
docker run --name booking-postgres -d \
  -e POSTGRES_DB=booking_db \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=postgres \
  -p 5432:5432 \
  postgres:16-alpine
```

### Шаг 2: Запуск бэкенда (Spring Boot 3.3.5)
```bash
./gradlew bootRun
```
*Бэкенд запустится на порту `8080`, автоматически применит миграции Flyway и инициализирует первичного администратора:*
- **Email:** `admin@booking.local`
- **Password:** `admin12345`

### Шаг 3: Запуск веб-фронтенда (React + Vite)
```bash
cd frontend
npm install
npm run dev
```
*Фронтенд будет доступен по адресу `http://localhost:5173` с автоматическим проксированием запросов `/api` на бэкенд.*

### Шаг 4: Сценарий демонстрации
1. Откройте `http://localhost:5173`.
2. Зарегистрируйте нового клиента через модальное окно или выберите услугу из каталога.
3. Выберите мастера и дату в календаре, выберите слот и подтвердите бронирование.
4. Откройте «Мои записи» и проверьте статус `PENDING`.
5. Войдите под администратором (`admin@booking.local` / `admin12345`) и подтвердите заявку (`CONFIRMED`).
