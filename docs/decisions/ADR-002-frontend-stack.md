# ADR-002: Выбор стека клиентской части (Web Frontend)

- Status: `ACCEPTED`
- Date: `2026-11-03`
- Decision owner: `Frontend Lead / Coordinator`

## Context

Проект требует создания адаптивного веб-приложения (SPA) для двух групп пользователей:
1. Клиенты/Гости: просмотр каталога, выбор специалистов, интерактивный выбор даты и слотов, оформление заявки (`PENDING`), личный кабинет с отменой бронирований.
2. Администраторы: модерация входящих заявок, CRUD каталога услуг и мастеров, интерактивная настройка расписания с валидацией интервалов.

Требования:
- `NFR-003`: адаптивность от 360px до 1920px (Mobile-first), поддержка Chrome, Safari, Firefox;
- `NFR-001`, `AC-004`: при получении HTTP 409 Conflict (`SLOT_ALREADY_BOOKED`) UI должен оперативно уведомить пользователя и автоматически инвалидировать/обновить сетку слотов без полной перезагрузки страницы;
- Строгая типизация API-контрактов между сервером и клиентом.

## Decision

Рекомендуется стек:
1. **Фреймворк и язык:** **React 18/19** с **TypeScript**.
2. **Сборщик:** **Vite** (быстрый HMR, легковесная конфигурация, поддержка proxy для dev-режима `/api/v1` -> backend).
3. **Стилизация:** **Tailwind CSS** (mobile-first классы, предсказуемая сетка для адаптивности 360–1920px, отсутствие накладных расходов во время выполнения).
4. **Управление серверным состоянием:** **TanStack Query (React Query v5)**:
   - Автоматическое кэширование, фоновая инвалидация данных;
   - Мгновенная инвалидация слотов мастера (`queryClient.invalidateQueries({ queryKey: ['slots', masterId, date] })`) при ошибке 409;
   - Управление состояниями `isLoading`, `isError`, retry-стратегии.
5. **Роутинг:** **React Router v6** (защищенные маршруты `RequireAuth`, `RequireAdmin`).
6. **HTTP-клиент:** **Axios** или нативный `fetch` с типизированными интерцепторами для обработки `401 Unauthorized` и `409 Conflict`.
7. **Компонентная база:** Headless UI / Lucide-react (иконки), минималистичные кастомные доступные компоненты на Tailwind без тяжелых зависимостей.

## Alternatives considered

| Option | Benefits | Costs/Risks |
|---|---|---|
| **Вариант 1: React + Vite + TypeScript + Tailwind CSS (Рекомендуется)** | 1. Наибольшая экосистема, богатейший выбор готовых паттернов.<br>2. TanStack Query решает проблему динамического обновления слотов (`AC-004`) в несколько строк.<br>3. TypeScript обеспечивает 100% совместимость с DTO бэкенда.<br>4. Tailwind идеально закрывает требования mobile-first адаптивности (`NFR-003`). | Требует базовой настройки роутинга и провайдеров. |
| **Вариант 2: Vue 3 + Vite + Pinia** | 1. Отличная реактивность, интуитивный Composition API.<br>2. Простота порога входа. | Меньше проверенных headless решений для сложных сеток бронирования по сравнению с React ecosystem. |
| **Вариант 3: Svelte / SvelteKit** | 1. Высокая производительность без Virtual DOM, малый размер бандла. | Меньшая распространенность готовых библиотек компонентов и утилит для тестирования по сравнению с React. |

## Consequences

- Исходный код фронтенда размещается в директории `frontend/` в монорепозитории.
- В dev-режиме Vite проксирует запросы `/api` на локальный порт бэкенда (`http://localhost:8080`), исключая проблемы с CORS при локальной разработке.
- Все DTO типизируются на TypeScript (`types/api.ts`).

## Requirements affected

- `REQ-001`–`REQ-014`, `NFR-003`, `AC-004`, `SCN-001`–`SCN-005`.
