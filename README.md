# Сервис записи на услуги

Full-stack веб-сервис онлайн-записи клиентов: расписание специалистов, личный кабинет клиента, административная панель и защита от двойного бронирования на уровне ядра PostgreSQL 16. Кейс №5 форума «Умная индустрия» (продвинутый уровень, 1.5x).

- Стек: Kotlin 2.0.21 / Java 21 / Spring Boot 3.3.5; React 18 / TypeScript 5.6 / Vite 6 / Tailwind CSS; PostgreSQL 16 с `btree_gist`.
- Статус: прототип `v1.0.0`, готов к демонстрации.

Материалы: паспорт кейса и расчёт ROI — `docs/submission/CASE-5-PASSPORT.md`; презентация — `docs/submission/PRESENTATION-10-SLIDES.md`; OpenAPI и архитектура — `docs/api/openapi.yaml`, `docs/architecture/`; схема БД — `src/main/resources/db/migration/V1__init_schema.sql`; шаблоны заявок — `docs/submission/APPLICATION-TEMPLATES.md`; отчёты QA — `docs/qa/`, `docs/review/`.

## Инструкция запуска

Требуется Docker, JDK 21 и Node.js 18 или новее.

1. СУБД: `docker compose up -d`.
2. Backend: `./gradlew bootRun`. Сервер на `http://localhost:8080`; Flyway создаёт схему, сидеры наполняют демо-данными.
3. Frontend: `cd frontend && npm install && npm run dev`. Откройте `http://localhost:5173`.

## Источник тестовых данных

Демо-данные создаёт `DemoDataBootstrapRunner` при первом запуске: 5 услуг (30 и 60 минут), 3 мастера, 7-дневное расписание с перерывами, 4 демо-записи.

**Обоснование:** набор моделирует реальные процессы сферы услуг — короткие и длинные услуги, пересечение компетенций мастеров (`M:N`), разрывные смены (`10:00–14:00` и `15:00–20:00`), конкуренция за слоты.

**Этическая и юридическая оговорка:** персональные данные реальных лиц и закрытые данные организаций не используются. ФИО вымышлены, email — домен `@booking.local`, телефоны — фиктивный диапазон `+79000000000..+79000000002`.

## Тестовые учётные записи

Создаются автоматически при старте. На странице входа доступны кнопки «Демо: Клиент» и «Демо: Администратор».

| Роль | Email | Пароль | Назначение при проверке |
| Клиент 1 | `client@booking.local` | `client12345` | Создание записи, личный кабинет, отмена |
| Клиент 2 | `maria@booking.local` | `client12345` | Изоляция чужих записей, конкурентное бронирование |
| Администратор | `admin@booking.local` | `admin12345` | Модерация, услуги, мастера, расписание |

## Проверка сценариев

**Двойное бронирование.** У «Алексея Громова» слот `11:00` уже занят демо-записью и не отображается в сетке. Создайте запись на `10:00` (Демо: Клиент) — слот исчезает из сетки. Повторный запрос на тот же интервал возвращает `409 Conflict (SLOT_ALREADY_BOOKED)`.

**Ролевой доступ.** Переход на `/cabinet` или `/admin` без входа блокируется `ProtectedRoute`; прямой `GET /api/v1/bookings/my` возвращает `401`. Под `CLIENT` видны только собственные записи; обращение к `/admin` возвращает `403`.

**Изменение расписания.** Администратор меняет окончание смены Алексея Громова с `20:00` на `18:00` — слоты после `18:00` исключаются из клиентской сетки.

## Архитектура и ограничения

Backend: Kotlin / Spring Boot. Frontend: React / TypeScript / Vite. Аутентификация — сессионная (`HttpOnly Cookie JSESSIONID`, `BCrypt cost 12`), роли `ROLE_CLIENT` / `ROLE_ADMIN`, защита от `IDOR` на уровне сервера. Защита от двойного бронирования — частичный констрейнт `EXCLUDE USING gist` в PostgreSQL 16 с расширением `btree_gist`.

**Ограничения:** единый часовой пояс `Europe/Moscow` при хранении времени в `UTC` (`TIMESTAMPTZ`); горизонт — 30 дней, шаг сетки — 30 минут, длительность услуг — 30 или 60 минут; клиент видит и отменяет только свои записи.
