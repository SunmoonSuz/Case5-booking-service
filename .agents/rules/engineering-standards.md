# Инженерные стандарты

- Соблюдай SOLID и ООП там, где они подходят предметной области; не вводи абстракции без причины.
- Соблюдай DRY, KISS и YAGNI совместно: не дублируй устойчивую бизнес-логику, но не создавай premature abstractions.
- Избегай God Object, Spaghetti Code, Shotgun Surgery, Primitive Obsession, Feature Envy, скрытых глобальных состояний, магических значений и чрезмерной вложенности.
- У каждого модуля/класса/функции должна быть ясная ответственность и контракт.
- Используй явную зависимость и понятные границы модулей; избегай циклических зависимостей.
- Код должен быть читаемым, типизированным в рамках выбранного языка и обрабатывать ошибки явно.
- Не меняй поведение за пределами scope без записи причины и согласования.
- Не добавляй новые технологии/библиотеки/паттерны без конкретного обоснования.


## Профиль проекта и стек

- Всегда учитывай `docs/PROJECT-PROFILE.md`; не предполагай full-stack scope.
- В новом backend-проекте Kotlin/JVM — предпочтительный профиль, если владелец не задал другой язык.
- Существующий стек, lockfiles, build files и утверждённые решения имеют приоритет над предпочтениями агента.
- В backend-only проекте не создавай frontend, UI, CSS или браузерные сценарии без отдельного требования.
- Spring Boot, JPA, Flyway, Kafka, PostgreSQL и coroutines выбираются по потребности, а не включаются комплектом.
