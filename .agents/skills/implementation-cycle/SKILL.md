# Implementation Cycle

1. Прочитай спецификацию и убедись, что она утверждена.
2. Прочитай `docs/PROJECT-PROFILE.md`; не предполагай full-stack scope.
3. Проверь DoR и составь traceability map `REQ -> AC -> implementation task`.
4. Изучи текущую кодовую базу и стек; используй существующие соглашения. Для нового backend-проекта Kotlin/JVM — предпочтительный профиль, Spring Boot рассматривай только при обосновании.
5. Подготовь минимальный технический дизайн и ADR для значимых решений.
6. Согласуй план работ и затронутые модули с пользователем.
7. Делегируй реализацию по профилю: `developer` — backend; `android-developer` — native Android; `frontend-developer` — web UI. Для `BACKEND_AND_ANDROID`/`BACKEND_WEB_AND_ANDROID` сначала зафиксируй API-контракт.
8. Получи отчёты профильных разработчиков, проверь diff и фактические команды тестирования.
9. После завершения основных срезов передай проект `tester` для независимого QA.
10. Закрывай дефекты циклом соответствующий developer -> tester regression.
11. Не переходи к релизу до положительного QA и code review.
